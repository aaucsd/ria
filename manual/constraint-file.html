How the constraint file is built

The algebraic model handed to the solver, section by section, as RIA emits it from a real event.

Every inversion is solved from a self-contained .rn file: variables with ranges, a chain of named definitions, the constraints, and the likelihood as the objective. invert() writes it to a temporary file by default; pass keep_model="event.rn" to keep it. Every shipped example does this, so after a run the exact file that was solved is in examples/models/. The file needs nothing else — you can re-solve it directly with the Rekin command line:

found = system.invert(image, truth=s1, budget=90, stall=5,  # a normal inversion
                      keep_model="event.rn")                # ...but keep the emitted model
# later, or on another machine:
#   rekin event.rn --budget 60

There are two encodings — COMPACT (the default, examples 1 and 3) and SPARSE (sparse=True, the fine-pitch examples 2, 4 and 5). Both sum the dark pixels in closed form so only fired pixels appear individually; they differ in how the full-sensor pattern mass is written. This page walks through example 1's emitted COMPACT model; the section at the end shows what changes under SPARSE.

1 · Variables

The decision variables are exactly the physical unknowns — four per source, nothing else (every derived quantity is a parse-time macro):

# Exact inversion model (ria.model_export), COMPACT encoding:
# 1 source(s) x (x,y,z,alpha), 14 fired of 144 pixels,
# 37 lenses.  The dark-pixel NLL is summed in closed form (it
# is linear in lam) and the grid normaliser S_j separates into
# per-lens row x column sums, so only fired pixels appear
# individually.
Variables:                   # the decision variables and their boxes
  Real x0 : [-25, 25]        # source x — box = the whole scintillator, mm
  Real y0 : [-25, 25]        # source y, mm
  Real z0 : [1e-06, 50]      # source depth, mm
  Real alpha0 : [1, 300]     # detected photons — the instrument's regime

The position boxes are the scintillator volume as declared in addScint — the search is the whole volume, with no starting guess. alpha is the expected detected photon count; its range [1, 300] states the instrument's operating regime (on the order of a hundred detected photons per event), which is given information about the detector, not part of the answer. With several sources the block repeats: x1, y1, z1, alpha1, and so on.

2 · The forward model, as macros

Everything between the variables and the constraints is a chain of Define name := expression lines. These are parse-time macros: each later occurrence of the name is replaced by the parenthesised expression before the model is parsed. No auxiliary variables are created — the solver sees a closed-form objective over the four unknowns — but the file reads as the physics, one named quantity per line, and each expression is written once rather than duplicated into every pixel term.

The chain, in order. Object distance:

Define u0 := (z0 + 5)        # object distance: depth + working distance, mm

Per-lens defocus blur at that distance — the thin-lens formula with the absolute value smoothed as sqrt(t² + 1e-12), plus the blur floor; squared, because everything downstream needs the variance:

Define s2_0_0 := ((0.75 * sqrt((20.477*(u0 - 6)/(6*u0) - 1)^2 + 1e-12) + 0.12))^2   # lens 0 blur variance at u0

Per-axis blob variance (the pixel's own second moment w²/12 folded in), the chief-ray blob centre, and the amplitude:

Define vx_0_0 := (s2_0_0 + 1.232536169)                       # blob variance + pixel w^2/12
Define cx_0_0 := (0 + (20.477/u0)*(x0 - 0))                   # chief-ray blob centre, x
Define g_0_0  := (2.25/(6.283185307*sqrt(vx_0_0*vy_0_0)*u0*u0))   # amplitude: solid angle / 2*pi*sigma

The pattern at a pixel — pixel area times the sum over lenses of a Gaussian density evaluated at the pixel centre. One such line per FIRED pixel only (14 here); the pixel coordinates are the constants:

Define pat_0_0 := (10.52476389*(g_0_0*exp(-((-21.15208333 - cx_0_0)^2/(2*vx_0_0)   # pixel area * sum over
                   + (-15.05166667 - cy_0_0)^2/(2*vy_0_0))) + g_0_1*exp(- ... )))  # lenses of blob density

The full-grid pattern mass S0 never sums 144 pixel terms: each lens's grid sum separates into a (row sum) × (column sum) product, one sx/sy pair per lens, and F0 collects the fired-pixel mass:

Define sx_0_0 := (exp(-(-21.15208333 - cx_0_0)^2/(2*vx_0_0)) + ... )   # lens 0: 12 column terms
Define sy_0_0 := (exp(-(-15.05166667 - cy_0_0)^2/(2*vy_0_0)) + ... )   # lens 0: 12 row terms
Define S0 := (10.52476389*(g_0_0*sx_0_0*sy_0_0 + g_0_1*sx_0_1*sy_0_1 + ... ))   # full-grid mass: row x column per lens
Define F0 := (pat_0_0 + pat_0_1 + ... + pat_0_13)                      # mass on the 14 fired pixels

And the expected rate per fired pixel — dark floor plus the normalised pattern scaled by the photon count, summed over sources when there are several:

Define lam_0 := (1e-09 + alpha0*pat_0_0/S0)   # rate at fired pixel 0: dark floor + normalised pattern

All constants are written with 10 significant digits, so the emitted model agrees with the numpy forward optics to float round-off. There is no approximation between simulation and inversion; the two are the same expressions.

3 · Constraints

A single-source COMPACT model has NO constraints — S0 is a macro, not a variable, so nothing needs enforcing. With more than one source there is one ordering row per adjacent pair, so that relabelling the sources does not count as a second optimum (this is the whole Constraints section of example 3's two-source model):

Constraints:                 # (empty for one source — S is a macro, not a variable)
  # break the source-label symmetry
  z1 - z0 >= 0 ~ 1e-6        # deeper source is source 1, tolerance 1e-6

4 · The objective

The Bernoulli negative log-likelihood of the observed image. The dark pixels' sum is closed-form — the NLL is linear in lam there — so the objective is the collapsed dark term plus one −log(1 − e^−lam + 1e-9) per fired pixel. This objective line is the only place the measurement enters the file:

Minimize:                    # the objective — the only place the image enters
  # Bernoulli NLL; the dark sum is closed-form:
  # sum_dark lam = sum_j alpha_j (1 - F_j/S_j) + m_dark*eps, m_dark = 130
  alpha0*(1 - F0/S0) + 1.3e-07 - log(1 - exp(-lam_0) + 1e-9) - ... ~ 1e-3   # dark term + one -log(p) per fired pixel

5 · The sparse (fired-pixel) encoding

At realistic-scale pitch (examples 2, 4, 5) the grid has 32 M pixels, and even the row × column sums of COMPACT would be enormous. sparse=True changes exactly one thing: at fine pitch the full-sensor mass S has a closed form — each lens blob is a normalised Gaussian whose density integrates to 1, so the blur cancels and only the geometric weight survives:

# SPARSE fired-pixel encoding: 1 source(s) x (x,y,z,alpha),
# 88 fired of 31834880 pixels, 37 lenses.
Define S0 := (2.25/(u0*u0) + 2.25/(u0*u0) + ... )       # analytic mass: sum_i a_i^2/u^2
Define F0 := (pat_0_0 + pat_0_1 + ... + pat_0_87)       # mass on the 88 fired pixels

Minimize:                                               # same objective shape as COMPACT
  # sum_dark lam = sum_j alpha_j (1 - F_j/S_j) + m_dark*eps, m_dark = 31834792
  alpha0*(1 - F0/S0) + 0.031834792 - log(1 - exp(-lam_0) + 1e-9) - ... ~ 1e-3   # 32M dark pixels in one term

Validity conditions, stated in the emitter's docstring: every blob must lie on the sensor (check system.visibility at plausible source positions), and the pixel must be small against the blur floor (at 6.9 µm against a 120 µm floor the tail-truncation error is around 1e-10). Under those conditions the sparse objective equals the COMPACT one term for term. At coarse binnings the grid itself aliases the pattern mass and the closed-form S no longer matches the grid sum — which is why COMPACT remains the default and sparse=True is an explicit choice.

Reading the tolerances

The ~ tol on each line is a declared tolerance: the line counts as satisfied within that band (1e-6 on the source-ordering row, 1e-3 on the objective). A returned point can sit anywhere inside the bands, so the objective value the solver reports can differ slightly from the exact likelihood at the same point. validate() recomputes the likelihood through the numpy optics, independently of the solver, and reports the relative model error — typically around 1e-5.

File size

Both encodings scale with the fired pixels, not the grid. Example 1's COMPACT 12×12 single-source model is 353 lines (14 fired pixels plus one row-sum and one column-sum macro per lens); example 3's two-source 24×24 model is 829. The SPARSE 32-Mpixel single-source model of example 2 is 426 lines — smaller than the two-source coarse file, because at most one pixel fires per detected photon.
