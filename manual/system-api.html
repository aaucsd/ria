Getting started

Building a system

Assemble an imager piece by piece, put an interaction in it, and recover that interaction from the picture.

The whole workflow

import ria                                    # the RIA package

FS = (6, 7.5, 9, 10.5, 12, 13.5, 15)          # focal lengths, cycled over the array
system = ria.imager()                         # an empty imager
system.addScint(size=(50, 50, 50),            # scintillator volume (x, y, z), mm
                working_distance=5.0)         # lens plane -> front face, mm
system.addLens(lenses=[{"position": tuple(p), "f": FS[i % 7], "aperture": 1.5}  # 37 records
                       for i, p in enumerate(ria.hex_layout(rings=3, pitch=3.6))],  # hex centres
               blur_floor=0.12)               # residual blur every blob carries, mm
system.addDetector(size=(46.15, 32.84),       # sensor active area, mm
                   pixels=(12, 12),           # coarse one-bit binning (example 1)
                   imaging_distance=20.477,   # lens plane -> sensor, mm
                   dark_count=1e-9)           # per-pixel background rate

s1    = system.addVertex([2, 2, 31], photons=77)   # the source: position mm, detected photons
image = system.forward(s1, seed=1)                 # simulate a measurement
found = system.invert(image, truth=s1,             # recover it from the image alone
                      budget=90, stall=5)          # solve <= 90 s, stop after 5 s no gain
Inversion(position=(1.290, 0.665, 9.945)mm, photons=300.0, error=21.109mm, status=local)   # <- what comes back

This is example 1 exactly — including its honest headline: at a coarse 12×12 binning the 21 mm miss is an information limit of the saturating one-bit sensor, not a solver failure (validate() below shows the recovered point explains the image better than the truth does; example 2 re-runs the same source at realistic-scale pitch and lands 0.055 mm from it). Every argument above is required; RIA sets no geometry by default. The sections below go through each call.

addScint — the active volume

size is the overall extent in mm, not a half-width. x and y are centred on the optical axis; z runs from the face nearest the lenses (z=0) into the volume. So size=(30, 30, 40) means x,y ∈ [−15, 15] and z ∈ (0, 40]. working_distance is the distance from the lens plane to that front face, mm.

system.addScint(size=(30, 30, 40), working_distance=5.0)   # extent mm; lens plane -> face mm
system.scint.bounds                  # the per-axis [min, max] the solver searches
system.scint.contains([2, 2, 20])    # True — inside the declared volume

addVertex refuses a position outside these bounds.

addLens — the optics

The lens array is a plain list of records, one per lens. Each record gives the lens centre on the lens plane, its focal length, and its aperture radius (the symbol a_lens), all in mm:

system.addLens(lenses=[{"position": (0.0, 0.0),  "f": 6.0, "aperture": 1.5},   # one record per lens
                       {"position": (3.6, 0.0),  "f": 7.5, "aperture": 1.5},   # centre mm, f mm, radius mm
                       ...],                                                    # ...37 in the examples
               blur_floor=0.12)      # array-wide residual blur sigma_0, mm

blur_floor is σ₀: residual blur every blob carries regardless of focus (diffraction, finite optics, sensor response). A helper generates the hex-packed position array the examples use; the records stay explicit either way:

pts = ria.hex_layout(rings=3, pitch=3.6)   # hex-packed centres:
                                           # 1 ring → 7, 2 → 19, 3 → 37

addDetector — the sensor

system.addDetector(size=(46.15, 32.84),  # active area (width, height), mm
                   pixels=(24, 24),      # one-bit pixels across that area
                   imaging_distance=20.477,  # lens plane → sensor, mm (S*)
                   dark_count=1e-9)      # per-pixel background rate ε

imaging_distance is S*, the lens-plane → sensor distance. Depth enters the image only through the magnification S*/u, which is how a flat array measures z. Finer binning carries more information and costs solve time roughly in proportion to the pixel count; see the sensor image for the saturation trade, and sparse=True below for fine-pitch sensors.

addVertex — an interaction

s1 = system.addVertex([2, 2, 31], photons=77)   # position (x, y, z) mm; detected photons

photons is the detected count α — the number of photons that reach the sensor, not the isotropic emission of the flash. Add several vertices and their light superposes in forward() (see "Several vertices in one image" below).

visibility — is this point measurable?

The argument is a source position (x, y, z) in mm — the same coordinates addVertex takes; the return is how many lenses land that point's blob on the sensor. A lens array has a depth-dependent acceptance: points too shallow or too far off-axis are imaged by no lens at all, and no photon budget changes that. With the 37-lens array built above:

system.visibility([2, 2, 31])       # 37 → every lens images s1
system.visibility([-24, -24, 0.2])  # 0  → a shallow corner no lens reaches

On a zero-visibility point forward() raises rather than returning a blank image, and its error message points back here. Check visibility() per vertex before trusting a multi-source separation (see the README).

forward — simulate the measurement

image = system.forward(s1, seed=1)         # one vertex, binary image
image = system.forward([s1, s2], seed=3)   # several — light adds

The image is binary: one bit per pixel, which is what a single-photon sensor returns. Each pixel fires with probability 1 − e−λ; the draw needs an explicit seed so a measurement is reproducible.

invert — recover the interaction

result = system.invert(image, budget=90, stall=5)             # real data
result = system.invert(image, truth=s1, budget=90, stall=5)   # simulation: adds .error
result = system.invert(image, budget=90, stall=5,             # keep the emitted model
                       keep_model="event.rn")         # ...written to this path
result = system.invert(image, budget=120, sparse=True, stall=5)   # fine-pitch sensors

invert writes the likelihood of the observed image as an algebraic model — the same optics as forward(), term for term — and solves it with the installed Rekin package. There is no separate fitting code; the solver's answer is the result. budget is the solve time in seconds; stall=N additionally stops the solve after N seconds without improvement (every shipped example passes it — 5 s, or 15 s on the hard three-source case). keep_model=path writes the emitted .rn file for inspection — every shipped example does. sparse=True selects the fired-pixel encoding, which is exact for fine-pitch sensors where the pixel is much smaller than the blur floor; the model then scales with the photon count rather than the pixel count. The fitted brightness is bounded to α ∈ [1, 300], the instrument's operating regime.

fieldmeaning
.positionrecovered vertex (x, y, z), mm
.photonsfitted detected-photon count α
.statusdelta-global (proved optimal), local (a verified local optimum), or best-effort (the best point found in budget)
.truththe true position, when supplied
.errorper-axis |error| — only when truth= was given

Several vertices in one image

A Compton scatter deposits energy twice; both flashes reach the sensor together, so one image contains superposed light. The syntax is the same — add the vertices, ask for that many sources back:

s1 = system.addVertex([5, 3, 30], photons=200)    # first flash
s2 = system.addVertex([-6, -2, 24], photons=150)  # second, dimmer flash

image = system.forward([s1, s2], seed=3)                  # light superposes
found = system.invert(image, truth=[s1, s2], sources=2)   # list back, brightest first

The emitted model contains one block of unknowns per source and a depth ordering (z₂ ≥ z₁) so that relabelling the sources does not count as a second optimum. All sources are solved jointly — the likelihood itself decides how to split the light. Each result is matched to its nearest true vertex for the error columns.

When separation is reliable: vertices well apart, both imaged by a decent share of the array, comparable brightness. It degrades when one source is much dimmer or sits in a poorly-imaged corner of the volume — the brighter fit absorbs its light. Check visibility() for each vertex first, and note that on a one-bit sensor positions are recovered much more tightly than per-source photon counts.

validate — check the answer independently

v = system.validate(found, image, truth=[((5, 3, 30), 200.0)])   # independent numpy check
v["model_rel_err"]                # emitted model vs numpy optics, relative
v["nll_solver"], v["nll_truth"]   # NLL of the fit and of the truth
v["beats_truth"]                  # fit explains the image at least as well

validate recomputes the likelihood of the recovered point through the numpy forward optics, with no solver code involved. It reports the solver's NLL, the numpy NLL, their relative difference (float round-off when the emitted model is faithful), the truth's NLL, and whether the recovered point explains the image at least as well as the truth does.
