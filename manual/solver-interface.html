How the image reaches the solver

What happens between invert(image) and the result you get back.

The pipeline

image ──▶ exact algebraic model (.rn) ──▶ rekin.solve() ──▶ Inversion
(nx×ny)   same expressions as forward      installed rekin    status: delta-global /
          10-significant-digit constants   package            local / best-effort

invert() writes the likelihood of the measured image as a plain-text model file and hands it to the installed rekin package (from rekin import solve). There is no grid search and no separate fitting code; the solver's answer, together with its status, is the result. Passing keep_model=path writes the emitted model to that path — every shipped example does this, so after a run the exact file the solver worked on is in examples/models/ and can be re-solved directly with rekin <model>.rn.

1 · One model, both directions

The forward simulation and the inverse likelihood are the same analytic function. A source at (x,y,z) with alpha detected photons gives per-pixel rates lam = eps + alpha·P(u,v) with ΣP = 1; each pixel fires with probability 1 − e−lam. P is chief-ray optics: per-lens Gaussian blobs with the pixel's own second moment (w²/12) folded into the variance, evaluated as density × area — deliberately exp/sqrt/ratio arithmetic only, so the solver's language expresses it exactly. There are no error functions, no lookup tables, and no approximation between forward and inverse.

2 · The model

The decision variables are exactly the physical unknowns: (x_j, y_j, z_j, alpha_j) per source. Positions carry the whole scintillator volume as their box; alpha is bounded to [1, 300], the instrument's operating regime (a few hundred detected photons) — given data about the source class, not a fit parameter. For more than one source, ordering constraints z_{j+1} ≥ z_j remove the label symmetry, and the rates superpose before the Bernoulli readout.

The forward chain — object distance u, per-lens defocus blur, blob centres, per-pixel pattern, rate lam, Bernoulli NLL — is written as parse-time macros (Define name := expression), so the file reads as the physics while the solver sees one closed-form objective over the 4·K unknowns. Constants are written to 10 significant digits; the emitted expressions are identical, term for term, to the numpy forward model. The constraint file page walks through a complete emitted model.

3 · Two encodings

Both encodings write the Bernoulli NLL with the dark-pixel sum collapsed in closed form — the NLL is linear in lam on dark pixels — to alpha_j·(1 − F_j/S_j) + m_dark·eps, where F_j is the pattern mass on the fired pixels. Only fired pixels appear individually in the file; the encodings differ in how the full-sensor mass S_j is written.

COMPACT (the default — examples 1 and 3): S_j is the pattern summed over the actual pixel grid, with each lens's grid sum separated into (row sum) × (column sum) macros. Exact at any binning, including coarse 12×12 and 24×24 grids.

SPARSE (invert(sparse=True), fine-pitch sensors — examples 2, 4 and 5): at fine pitch the full-sensor mass is analytic, S_j = Σ_i a_i²/u_j², because each lens blob is a normalised Gaussian whose blur cancels on integration. The file then scales with the photon budget rather than the pixel count — a 32-Mpixel sensor emits a smaller file than a 12×12 one. The closed form is valid when pixels are much smaller than the blur floor and every blob lies on the sensor; at coarse binnings the pixel grid itself deviates from the continuous mass, which is why COMPACT is the default and sparse=True is an explicit choice.

4 · Status

The solver reports one of three statuses, and the library passes it through unchanged:

statusmeaning
delta-globalglobal optimality proved to the stated tolerance
locala certified local optimum
best-effortthe best point found; no certificate

A status is never rounded up. In the shipped examples the imaging inversions return local (or best-effort on the three-source frontier of example 5); the design solves of example 6 return local and best-effort.

5 · Checking the answer: validate()

v = system.validate(inversion, image, truth=[(position, photons)])   # independent numpy check
v["model_rel_err"]   # emitted model vs numpy forward optics (~1e-5)
v["nll_solver"], v["nll_truth"], v["beats_truth"]   # fit NLL, truth NLL, fit at least as good?

validate() recomputes the model's NLL through the numpy forward optics, with no solver code involved. A small model_rel_err confirms the emitted model matches the forward simulation to float round-off. Comparing nll_solver against nll_truth shows whether the recovered configuration explains the image at least as well as the ground truth does. At coarse binnings it genuinely can while being far from the truth — a saturating one-bit sensor at low resolution does not always identify the source. That is a property of the measurement, not of the solver, and it is visible: the recovered point has the lower NLL.
